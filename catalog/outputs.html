Output Map

Where every skill writes its deliverables — canonical paths relative to your project root. Click any skill chip to open that skill's reference page.

Output file types

Each skill produces one or more of these file formats. Understanding the role of each type tells you which files to read, which to open in a tool, and which are generated automatically.

.md

Markdown deliverable

Human-readable stakeholder artifact — the primary output of almost every skill. Source of truth for specs, maps, glossaries, and design decisions.

.drawio

Draw.io diagram

Visual representation generated or synced from the paired .md or .json source. Always named with the same stem as its source file (e.g. domain-model.drawio pairs with domain-model.md). Never the source of truth — regenerated on demand.

.json

Machine-readable data

Structured data consumed by tools and sync scripts — not for direct reading. Examples: story-graph.json (story structure), domain-model.json (domain entity graph), state.json (UX mockup shared state).

.yaml / .aria.yaml

ARIA descriptor

Accessibility-focused screen descriptor produced by abd-ux-mockup and abd-context-app-extractor. One file per screen or extracted page — describes controls, roles, and interaction structure in a form agents can read and test against.

.png

Screenshot

Visual evidence captured alongside ARIA descriptors by abd-context-app-extractor. Stored next to the .aria.yaml for the same page slug. Not generated — captured from a live or sandboxed application.

How output paths resolve

When a skill decides where to write, it walks this priority list and stops at the first match:

  1. 1. What you said. If you name a file or folder explicitly, the skill uses exactly that — no questions asked.
  2. 2. cdd-context-index.md at the workspace root. Any deliverable moved off its canonical path must be recorded here so skills can find it without asking. One row per non-standard artifact.
  3. 3. Where the work already lives. If a previous phase output sits in a recognisable folder the skill writes next to it, keeping the chain coherent.
  4. 4. Canonical path — this map. The paths shown below. Used when none of the above applies.
  5. 5. Workspace root. Last resort only, when no convention applies at all.

File name — once the folder is resolved, the skill checks its own reference/output.md first (only present when the skill breaks the default — multiple outputs, non-.md deliverable, project test folder). Otherwise it uses the name shown in this map.

Source of truth — common/reference/folder-conventions.md in the repo. common/reference/skill-workflow.md § Output file resolution defines the algorithm above.
